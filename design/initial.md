# Initial feature: Items grid

## Goal

Desktop app that shows a table of items stored in a local SQLite database. The window opens on the Items page, which hosts a reusable `GridView` component.

## Stack

- .NET 10, Avalonia 12, CommunityToolkit.Mvvm.
- EF Core with SQLite, code-first migrations.
- `Microsoft.Extensions.Hosting` for DI, configuration and logging.
- Bogus for seed data.
- Tests: xUnit in a separate project `tests/TestGrid.Tests`. The application itself is a single project `src/TestGrid`.

## Data model

Table `Items`:

| Column | Type | Notes |
|---|---|---|
| Id | Guid | PK. Regular `Guid.NewGuid()` (not v7), generated by the app. |
| Name | string | |
| Quantity | int | |
| Price | float | |
| ModifiedOn | DateTimeOffset | Always UTC. |

SQLite storage decisions:

- `ModifiedOn` is stored as UTC ticks (`long`) through a value converter, so `ORDER BY` and range comparisons work in SQL. SQLite has no native `DateTimeOffset`.
- `Id` is stored as `TEXT` (EF default). Ordering by `Id` is then lexicographic on the string. This is stable and good enough as a tiebreaker.

## ModifiedOn maintenance

`ModifiedOnInterceptor : SaveChangesInterceptor` sets `ModifiedOn = DateTimeOffset.UtcNow` for every `Added` and `Modified` `Item` entry, in both sync and async `SavingChanges` overloads. It is registered through DI and added to the `DbContext` options.

## Startup

1. Build host (DI, logging).
2. `Database.Migrate()` applies migrations.
3. `DbSeeder.SeedIfEmpty` inserts 1000 generated rows when the table is empty.
4. Show `MainWindow`.

Database file: `%LocalAppData%/TestGrid/items.db`.

## Logging

Default Microsoft logger. The category `Microsoft.EntityFrameworkCore` is set to `Warning`, so SQL commands and queries are never logged.

## UI

- `MainWindow` shows `ItemsView` (the only page).
- `ItemsView` / `ItemsViewModel`: the page. Hosts `GridView`.
- `GridView` / `GridViewModel`: custom reusable component.
  - Uses an `ObservableCollection<ItemViewModel>`.
  - `ItemViewModel` is an `ObservableObject`, so every item is observable.
  - `GridViewModel` loads rows from the database itself (all rows in the initial feature; paged since feature 2) (through `IDbContextFactory<AppDbContext>`). The page view model does not touch the database.
  - Built on `Avalonia.Controls.DataGrid` with explicit columns. The `Id` column is not shown.
- View models are created through DI.

## Testing

- Interceptor sets `ModifiedOn` on create and update, in UTC.
- Seeder seeds an empty database with 1000 rows and does nothing on a non-empty one.
- `GridViewModel` loads all rows.
- Tests use an in-memory SQLite connection.

## Smoke test

Run the app: the window shows the grid with 1000 rows, no `Id` column, and the log has no SQL output.

## Implementation notes

- Packages: Avalonia 12.1.5, Avalonia.Controls.DataGrid 12.1.2 (a v12 build exists, so the DataGrid is used as decided), CommunityToolkit.Mvvm 8.4.2, EF Core 10.0.14.
- `DesignTimeDbContextFactory` lets `dotnet ef` create migrations without starting the Avalonia app.
- `ItemsViewModel` receives `GridViewModel` through DI and exposes it as `Grid`; `ItemsView` binds it as the `GridView` data context. `GridView` triggers the load when it is shown.
- The build prints an "Avalonia Accelerate Community requires telemetry" notice; it comes from the Avalonia package and is not configurable on the free tier.
- Superseded in feature 2: the grid no longer loads all rows; it loads pages by cursor. Column bindings are `OneWay`.
- Feature 3 starts the host (`host.Start()`) after migration and seeding, so hosted services run.
